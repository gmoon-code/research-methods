# v2.17 Teacher Workspace T6 Chat Controls Contract

## Purpose

T6 makes the existing Chat Controls area functional inside the authenticated Teacher Workspace.

The first T6 implementation provides teacher-facing Research Chat configuration status, privacy boundaries, and clearly labeled controls that affect only the current browser session.

T6 does not introduce class-wide Research Chat policy storage.

T6 does not create a new teacher Chat-policy backend route.

T6 does not expose student Research Chat conversations.

## Recovery point

- commit `b489b45f5f28549d4a5bcde344d904477816cf4b`
- tree `1adad4c26fc0e69957755481af221a242d9b18fc`

T5 remains frozen while T6 is developed.

Production remains at:

- commit `837a13476c0334ba6f99aff94d111567be9870f4`
- recovery ref `backup/production-stable-2026-09-15-v2.16.1`

T6 must not alter production or the production recovery point.

## Existing Research Chat architecture

The existing student Research Chat architecture remains authoritative.

Current behavior includes:

- the Research Chat endpoint is selected only by owner-controlled `assets/runtime-config.js`
- the production endpoint is the configured Cloudflare Workers endpoint
- the current free edition uses Cloudflare Workers AI
- student class Chat codes remain browser-session data
- the existing Chat enable preference is stored only in `sessionStorage`
- the existing Chat enable preference affects only the current browser session
- the existing student `Use my current project context` setting remains controlled from the student Research Chat experience
- project context is minimized before network transmission
- raw datasets and other excluded sensitive fields remain outside Research Chat requests
- only verified literature sources are eligible for source-specific Research Chat citation support
- student Research Chat transcripts are not included in `rms_student_review` packets
- Teacher Workspace review imports do not contain Research Chat transcripts

T6 must preserve those behaviors.

## Truthful control boundary

The current application has no persistent teacher Chat-policy route.

The current application has no server-side class-policy database.

The current application has no mechanism for a Teacher Workspace switch to change Research Chat behavior automatically across student devices.

T6 must therefore describe all browser-local controls as browser-local.

A T6 control must never use wording that implies:

- all students have been changed
- a class-wide setting has been changed
- another device has been changed
- a student project has been changed
- the Cloudflare Worker configuration has been changed
- a persistent server policy has been saved

Any future class-wide Chat policy requires a separate contract covering storage, authorization, retrieval, student application behavior, migration, privacy, recovery, and failure handling.

## Functional T6 scope

The first T6 Chat Controls area contains four functional groups:

1. Research Chat service configuration status
2. authenticated teacher-session status
3. current-browser Chat preview controls
4. student privacy and policy boundaries

These groups are defined below.

## Research Chat service configuration status

Chat Controls may read the existing owner-controlled runtime configuration.

The UI may display:

- whether a Research Chat endpoint is configured
- the configured endpoint origin or hostname
- the runtime release version
- whether the runtime identifies itself as the free edition

The UI must describe this as configuration status.

The UI must not claim that configuration status proves current Worker availability.

T6 does not perform an automatic background health request.

T6 does not add polling.

T6 does not add monitoring.

T6 does not add a new Chat status network endpoint.

## Endpoint security

The Teacher Workspace must not provide an endpoint editor.

The Teacher Workspace must not permit an arbitrary endpoint to be entered.

The Teacher Workspace must not modify `assets/runtime-config.js`.

The existing owner-controlled endpoint boundary remains unchanged.

Credential-bearing URLs remain prohibited.

Teacher Chat Controls must not weaken the existing `workers.dev` production endpoint restrictions.

## Teacher authentication status

Chat Controls may display whether the existing signed teacher session is currently active.

This status comes from the existing `RMSTeacherSession` API.

T6 must not create a second teacher authentication system.

T6 must not store the teacher access code.

T6 must not display the teacher access code.

T6 must not expose the signed teacher session token.

The Teacher Workspace remains hidden until the signed teacher session has been verified.

## Current-browser Chat preview preference

T6 may expose the existing Research Chat enabled preference through the existing `RMSAI` configuration API.

This control is a local preview control.

Its UI must prominently state:

`This browser session only`

Changing this preference may alter Research Chat availability only for pages using the same browser session and origin.

The control must use the existing Research Chat session preference.

T6 must not create a second enablement storage key.

T6 must not use `localStorage` for this preference.

T6 must not persist this preference to a server.

T6 must not write this preference into a student project.

T6 must not present this control as a classroom policy.

## Existing local preference API

The existing Research Chat adapter currently supports:

- `RMSAI.getConfig()`
- `RMSAI.setConfig({ enabled: boolean })`
- `RMSAI.chatConfigured()`
- `RMSAI.chatEnabled()`

T6 may use these existing APIs.

T6 must not mutate the Research Chat endpoint through `RMSAI.setConfig`.

The existing adapter intentionally ignores endpoint mutation.

## Student class Chat code status

T6 may display whether a student class Chat code is currently present in this browser session.

The UI may display only a boolean-style state such as:

- class Chat code present in this browser session
- no class Chat code present in this browser session

The code value itself must never be displayed.

T6 may provide an explicit action to clear the student class Chat code from the current browser session using the existing Research Chat adapter.

The clear action must state that it affects only this browser session.

Clearing the class Chat code must not clear the signed teacher session.

Clearing the class Chat code must not alter the configured endpoint.

Clearing the class Chat code must not change student project content.

Clearing the class Chat code must not send the code anywhere.

## Research Chat class code and teacher access code separation

The student class Chat code and the teacher access code are separate credentials.

T6 UI copy must keep them clearly distinct.

The Teacher Workspace must never suggest that clearing the student class Chat code signs the teacher out.

The Teacher Workspace must never use the teacher access code as a student Research Chat code.

## Student project-context control

The existing student-facing setting:

`Use my current project context`

remains a student Research Chat control.

T6 must not change this setting.

T6 must not force project context on.

T6 must not force project context off.

T6 must not inspect a student's current value for this setting.

T6 may explain that students control whether relevant minimized project context is included with a Research Chat request.

## Student authorship safeguards

Existing Research Chat authorship protections remain unchanged.

T6 must not add teacher controls that weaken student reasoning safeguards.

T6 must not provide controls that instruct Research Chat to complete unfinished student research decisions automatically.

T6 must not provide controls for changing hidden system prompts.

T6 must not provide controls for changing model instructions.

T6 must not provide controls for bypassing current instructional boundaries.

## Transcript privacy

This includes:

- student questions
- assistant responses
- conversation history
- message timestamps tied to student conversations
- conversation IDs
- hidden conversation metadata
- Research Chat event history
- student prompt text

T6 must not read `aiHelper.messages` from student projects.

T6 must not read `aiHelper.events` from student projects.

T6 must not add transcript fields to `rms_student_review`.

T6 must not add transcript fields to `rms_teacher_feedback`.

T6 must not send transcript content to Teacher Workspace.

T6 may display a static privacy statement confirming this boundary.

T6 status and local controls must continue working with zero imported review packets.

## Pure status model

Teacher-facing Chat status derivation should use a pure function in `assets/teacher-workspace-data.js`.

The proposed public function is:

`deriveTeacherChatControlsStatus(input)`

The input should contain only explicit status values supplied by the authenticated page.

Permitted input fields are:

- runtime version
- free-edition boolean
- configured Research Chat endpoint
- teacher-session active boolean
- local Research Chat enabled boolean
- local class Chat code present boolean

The pure function must not read:

- `window`
- `document`
- `sessionStorage`
- `localStorage`
- student projects
- imported review packets
- Research Chat messages
- network responses

The UI gathers explicit current-page state and passes only those values into the pure function.

## Proposed status model

The T6 status model should contain:

- `service`
- `teacher_session`
- `local_preview`
- `privacy`

### Service

`service` should contain:

- `configured`
- `endpoint_origin`
- `runtime_version`
- `free_edition`

`endpoint_origin` must contain only a safely parsed origin.

If the endpoint is absent or invalid, it remains unavailable.

The model must not fabricate service availability.

### Teacher session

`teacher_session` should contain:

- `active`

This is descriptive status only.

### Local preview

`local_preview` should contain:

- `chat_enabled`
- `class_code_present`
- `scope`

`scope` is fixed to:

`browser_session_only`

### Privacy

`privacy` should expose fixed booleans confirming:

- transcripts_exposed is false
- project_context_teacher_controlled is false
- endpoint_teacher_editable is false
- classwide_policy_available is false

These values document the T6 architecture.

They must not be inferred from student behavior.

## Determinism

`deriveTeacherChatControlsStatus` must be deterministic.

The same input must produce the same output.

The function must not depend on:

- current time
- random values
- browser state
- network state
- packet ordering

## Immutability

The returned T6 status model and its public nested structures must be frozen.

The input object must not be mutated.
