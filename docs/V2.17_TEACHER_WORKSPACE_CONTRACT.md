# Research Methods Studio v2.17 Teacher Workspace Contract

## Status

Development contract for feature/v2.17-teacher-workspace.

Production baseline:

- Commit 837a13476c0334ba6f99aff94d111567be9870f4
- Recovery branch backup/production-stable-2026-09-15-v2.16.1
- Production remains untouched while v2.17 is developed.

## Purpose

v2.17 will turn the existing authenticated teacher utilities into a coherent
Teacher Workspace while preserving the current student experience, privacy
boundaries, and zero-cost deployment architecture.

## Non-negotiable boundaries

1. Teacher authentication remains server-verified.
2. A client-side URL, query parameter, or JavaScript flag must never activate
   teacher privileges.
3. Teacher access remains separate from the student class Chat code.
4. Teacher credentials must never be stored in the public repository.
5. Teacher credentials must never be placed in localStorage.
6. Existing production Worker behavior remains unchanged during milestone T1.
7. Student project data must not be uploaded merely to support the Teacher
   Workspace.
8. Raw datasets remain excluded from student review packets.
9. Full manuscript text and full source notes remain excluded from the current
   review packet unless a later explicit design change is separately reviewed.
10. Software-generated competency indicators remain instructional evidence and
    must not become automatic grades.
11. Teacher judgment remains distinct from software diagnostics.
12. Student work must never be silently changed from the Teacher Workspace.
13. Feedback exchange remains explicit and auditable.
14. Current v1.7 review and feedback packets remain compatible during T1.
15. The student workspace must continue functioning when teacher features are
    unavailable.

## Teacher entry behavior

teacher.html remains the authentication entry point.

After a valid teacher session is verified, teacher.html will eventually send
the teacher to teacher-workspace.html.

teacher-workspace.html must verify the teacher session again before exposing
teacher tools.

If verification fails, the page must fail closed and return to teacher.html.

The Teacher Workspace must provide an explicit way to leave teacher mode.

Leaving teacher mode must clear the teacher session and return to the normal
student site.

## Teacher Workspace information architecture

The planned primary areas are:

### Overview

A concise class-level summary of imported project review information.

It should surface:

- Number of imported projects
- Checkpoints awaiting teacher review
- Revision requests
- Projects with unresolved blockers
- Ethics teacher-review cases
- Do-not-facilitate cases
- Locked protocols
- Projects with stored analysis records

Overview is instructional triage, not a grading leaderboard.

### Review Queue

The queue should organize work that needs teacher attention.

Initial queue categories:

- Awaiting review
- Revision requested
- Ethics review
- Do not facilitate
- Blocked
- No immediate teacher action

Each queue item must explain why it appears there.

### Students

A project list based on explicitly imported student review packets.

The first version may show only information already contained in the existing
review packet.

It must not imply that omitted student work has been inspected.

### Assignment Setup

Reserved for a later milestone.

Planned capabilities may include:

- Course or section
- Required checkpoints
- Stage expectations
- Source expectations
- Ethics requirements
- Chat policy
- Transfer-task policy
- Teacher-authored guidance

Assignment setup must use an explicit import/export mechanism until a secure
server-side class configuration design is separately approved.

### Analytics

This area may organize existing competency and class-level evidence.

It must preserve the distinction between:

- Independent evidence
- Supported performance
- Scaffold exposure
- Revision history
- Teacher ratings

Analytics must not automatically assign grades.

### Chat Controls

This area may expose approved teacher-facing Research Chat configuration and
status.

It must not expose student Research Chat transcripts by default.

Student Chat privacy boundaries remain unchanged unless a later design is
explicitly reviewed.

### Recovery

This area will organize teacher-facing backup, restore, and operational
recovery functions.

Destructive actions require explicit confirmation.

## Packet architecture

The current rms_student_review packet remains the source for the initial
Teacher Workspace.

During T1:

- Packet version stays 1.7.
- Raw datasets remain omitted.
- Full paper text remains omitted.
- Full source text and notes remain omitted.
- Existing feedback-packet behavior remains compatible.

A future Student Project Inspector may require a separately designed expanded
inspection packet.

That packet must be opt-in, privacy-reviewed, versioned, and intentionally
scoped before implementation.

## Persistence

T1 will not introduce a server database.

The initial Teacher Workspace will first prove the user interface and packet
workflow without changing backend storage.

Persistent local class storage may be added in a later milestone after its
privacy, deletion, recovery, and migration behavior has been specified and
tested.

## T1 implementation scope

T1 is limited to:

1. teacher-workspace.html
2. authenticated teacher-session gate
3. dedicated Teacher Workspace shell
4. navigation for planned teacher areas
5. Overview placeholder
6. Review Queue placeholder
7. Students placeholder
8. clear View student site action
9. clear Leave teacher mode action
10. accessibility and responsive behavior
11. automated regression coverage

T1 must not yet:

- change Worker routes
- change secrets
- change student packets
- add server persistence
- add student accounts
- expose raw student data
- alter student progress
- alter student Chat behavior
- alter production release manifests

## Development rule

Every Teacher Workspace milestone must pass existing student regressions before
it may be considered for merge.

The known-good production recovery point must remain untouched throughout
v2.17 development.
